## What changed

- Three dynamic priorities: **Standard Glazed** (efficiency), **Jam Filled** (balanced) and **Cream Filled, Cherry on Top** (performance). Continuous On reassesses; Off completes one search and holds the result. These are measured objectives, not presets.
- Persistent activity status across pages; **Live dashboard** and **Adjust this tune**; six gap-aware trend charts for ASIC/VRM temperatures, power, useful TH/s, J/TH and ASIC errors, plus real controller decisions. Reported J/TH is not wall-meter efficiency.
- Separate current-work **Pool share difficulty** and **Network difficulty** for each pool on Overview and Tuning; unavailable work is not shown as zero.
- A read-only physical Tuning display page. No screen action starts tuning or accepts its waiver. If protective backoff reaches the minimum clock, the point is marked rejected under the current constraints, with the instantaneous readings kept separately from completed measurement means.

This family retains shufps v1.1.1-rc1 and adds board/per-chip ASIC error percentages. Standard 320×170 stays the default; the saved 480×320 RGB/BGR paths remain physically unqualified. The editor uses the actual detected board clock maximum; unavailable metadata does not invent a higher cap.

## Update and enable

In **5tratumOS → Settings → Updates**, install **0.8.50 on MAIN**, or **0.8.50-dev if already on DEV**, then reload the portal. Keep your existing OS channel; a firmware beta does not require changing it. If this miner is already running a tuning candidate, first open its Tuning page, select **Disable and restore backup**, and wait until the original settings are confirmed restored and tuning is inactive. If already paused and ordinary restoration is waiting, use the separate **Restore original settings and resume mining** action and wait for completed verification. Do this before installing another firmware pair; an accepted Stop request alone is not completed restoration. On the correct miner choose **Firmware update → BETA → Check for updates**, confirm **NerdQAxe++ Beta10**, then **Install firmware → Confirm install**. Keep power connected until **Firmware installation verified** appears. The OS installs and verifies both images and saved settings; future compatible betas are discovered without an OS release for every beta. [Complete update instructions](https://github.com/WillItMod/5tratumFW/blob/main/DOWNLOADS.md#update-through-5tratumos).

For manual OTA, verify the checksums, upload `esp-miner-NerdQAxe++.bin` first, wait for restart, then upload this release's `www.bin` and follow the model guide's refresh/restart checks. Keep authentication enabled and verify both versions and original settings. The one-click updater does not convert stock firmware.

Open **Tuning**, choose the objective and compatible limits, then save. The recommended starting targets are **60°C ASIC /70°C VRM**, or lower where required. Warnings begin above 60°C ASIC /70°C VRM, with stronger warnings above 65°C ASIC /at 80°C VRM. These are project guidelines, not universal safe limits. Performance cannot test above its saved clock ceiling.

Read the experimental disclaimer and accept the unticked risk acknowledgement for this run before **Start tuning**. Changing settings can cause instability, heat, damage, interrupted mining or loss; use it at your own risk. **Adjust this tune** edits an admitted run without a second Start. Small probes are checked against measurement noise; no improvement is a valid result.

**Disable and restore backup** requests the immutable, identity-bound original settings saved before the first run. Later runs do not replace them. Verify the completed saved/live readback; unsafe conditions can leave restoration pending without clearing faults. The backup survives restarts; tuning never starts automatically after boot, even with Continuous On saved. Keep your separate private recovery backup.

For an already paused miner, **Restore original settings and resume mining** is a separate explicit action: it validates the powered-off state, restores and independently verifies the durable original configuration, requests normal startup, then verifies live settings, fans and mining. It keeps tuning off, never clears a hardware fault and never bypasses startup protection. New manual/scheduled control or an update cancels a pending recovery; a blocked attempt requires another explicit request.

When an ordinary measured trial is rejected, the controller returns to its better measured point when headroom permits. If protective backoff exhausts the permitted clock range, or repeated error-correction windows are exhausted, the failed point is retained in the decision history. A clock-floor rejection records the initiating readings; error exhaustion records the actual completed window means, without inventing an improvement score. These two soft tuning failures can make one guarded automatic recovery attempt: pause and cool, validate protection and sensors, restore and independently verify the immutable pre-tune settings, then resume and verify normal mining with tuning off. Cooling admission requires the applicable temperature headroom; Gamma holds mining work until fresh powered ASIC/regulator/fan readings pass. Nerd applies the extra 5°C margin before startup and continues to enforce user ceilings during powered startup. A real hardware fault, invalid backup, missing telemetry, failed verification or newer manual/scheduled control blocks or cancels recovery. There is no automatic fault clearing, MCU reboot or repeated retry. The original point can differ from tighter tuning targets selected later; improve cooling or review the permitted range before another Start.

Changing operating settings can cause instability, overheating, hardware damage, interrupted mining or financial loss. Use experimental tuning at your own risk. The explicit disclaimer/waiver is required for each Start; it does not disable hardware protection. [Full Tuning guidance](https://github.com/WillItMod/5tratumFW/blob/main/docs/autotuning.md).
