# Optional Gamma Ethernet component

This is original GPL-3.0-or-later code for an optional SPI W5500 MACRAW interface. It does not import an external W5500 driver or change the existing GPL firmware's licensing. The component has no startup constructor: only an explicit `gamma_ethernet_start()` call allocates resources or accesses pins.

The integration must establish a supported Bitaxe Gamma identity, confirm the saved Ethernet option, exclude BAP on the shared GPIO39/40 pair, and initialize ESP-NETIF and the default event loop before starting this driver. Start and stop are serialized management operations. The status getter is concurrent-safe. The netif handle remains valid until stop and can be used to update its hostname. The driver does not choose a sticky default route.

The fixed connection is SPI2, MOSI GPIO40, MISO GPIO39, clock GPIO41 and chip select GPIO42, mode 0 at 20 MHz. There is no interrupt or reset GPIO. A software register reset and polling are used. A missing chip is rejected by its version register before any W5500 register write, and startup failures release resources owned by this component. An already-owned SPI bus is not adopted or freed.

The original protocol engine uses socket 0 in MACRAW mode, with its full 16 KiB receive and transmit banks and the other socket banks disabled. It retains broadcast, multicast and IPv6 packets for the host stack. Counter reads are repeated until stable, with an attempt bound. Hardware command completion, send completion and SPI operations have finite waits. Packet headers, ring size, caller capacity and Ethernet frame limits are checked before copying. The driver pads short transmitted Ethernet frames to 60 bytes without FCS. It never retries an uncertain transmitted frame itself.

ESP-NETIF provides the Ethernet TCP/IP stack, DHCP and standard Ethernet IP events. The netif's route priority is 100; the integrating network policy can give Wi-Fi a lower priority while Ethernet is enabled. Cable loss clears the driver's usable IP snapshot immediately and invokes the standard netif disconnect action. Actual DHCP timers and default route policy belong to ESP-NETIF and the integrating component. `last_error` is a diagnostic of the most recent failure, while `started`, `available`, `link_up` and `has_ip` describe current readiness.

SPI operations and register/ring changes are serialized. The network stack receives an independently allocated frame only after the SPI mutex is released; the registered RX free callback owns its release after handoff. Netif start/connect/disconnect actions also run outside the SPI mutex, permitting immediate DHCP/ARP output without recursive lock acquisition. With `CONFIG_SPI_MASTER_ISR_IN_IRAM=y`, the SPI interrupt is allocated with `ESP_INTR_FLAG_IRAM` so queued completion can run while flash cache is disabled; this adapter has no user ISR callbacks. SPI descriptors and DMA storage persist until completion. If a hardware transaction cannot be drained within the cleanup deadline, that storage and its SPI device are quarantined until restart instead of freeing memory still referenced by DMA. The network interface is already stopped, allowing Wi-Fi fallback.

## References and qualification limits

The register and SPI facts were checked against the official [WIZnet W5500 datasheet v1.1.0](https://docs.wiznet.io/img/products/w5500/W5500_ds_v110e.pdf), especially the SPI format, socket memory, MACRAW mode, status, pointer and command registers. ESP-NETIF integration follows the [ESP-IDF 6.0.2 custom I/O driver documentation](https://docs.espressif.com/projects/esp-idf/en/v6.0.2/esp32s3/api-reference/network/esp_netif_driver.html) and public headers, with the SPI master public API from the same SDK.

The receive engine currently interprets the two-byte big-endian MACRAW length as including those two bytes and passes the following Ethernet frame to the host. The cited datasheet does not explicitly specify this receive-record layout or FCS delivery. Those details, padding/FCS behavior, module wiring, link negotiation and sustained RX/TX operation must be confirmed on the actual module. Application and WWW OTA must also be tested with Ethernet alone while flash writes and network traffic overlap. No physical Ethernet module has been qualified by the host simulator or target compilation. This optional path must retain that experimental limitation.

Run `python3 tools/test_gamma_ethernet.py` from the repository root. The two sanitizer-backed host executables exercise the actual protocol engine and adapter against original register, SPI, RTOS and netif test doubles. They cover initialization, missing hardware, all bank allocations, 16 KiB and 16-bit wrap, header/payload bounds, unstable counters, padding, link loss/reconnect, command/send/reset timeouts, frozen time, SPI errors, startup cleanup, persistent DMA on timeout, RX ownership and immediate stack transmit reentry. They perform no network or device writes.
