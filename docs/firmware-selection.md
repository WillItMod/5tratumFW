# Firmware selection and repository structure

For downloads, start with **[Gamma, QAxe or OctAxe](../DOWNLOADS.md)**. This page documents the detailed model and build requirements.

## Choose before downloading

| Model | Source/build | OTA application filename | Matching website | Current support |
| --- | --- | --- | --- | --- |
| Gamma 601/602 | Root; `bash tools/build_5tratumfw.sh` | `esp-miner.bin` | Included in the application; Gamma `www.bin` is optional for separate-WWW use | Public Beta15 **experimental** adaptive tuner. Gamma 602 tuner admission/restore and W5500 hardware remain unqualified. [Fast-error software validation](validation-autotune-fast-errors-20261104.md) |
| NerdQAxe++ / NERDQAXEPLUS2 / BM1370×4 | `firmware/nerdqaxe/`; `bash tools/build_5tratumfw_qa.sh` from that directory | `esp-miner-NerdQAxe++.bin` | QAxe `www.bin`, same version/package | Public Beta12 **experimental** adaptive tuner; standard 320×170 default. [Fast-error software validation](validation-autotune-fast-errors-20261104.md); larger panel unqualified. |
| NerdOCTAXE-γ / NERDOCTAXEGAMMA / BM1370×8 | `firmware/nerdqaxe/`; `bash tools/build_5tratumfw_oct.sh` from that directory | `esp-miner-NerdOCTAXE-Gamma.bin` | OctAxe `www.bin`, same version/package | Public Beta10 **experimental** adaptive tuner; owned PCB 2.2 scope, standard 320×170 default, larger panel unqualified. [Fast-error software validation](validation-autotune-fast-errors-20261104.md). |
| Other variants/revisions | None qualified | None | None | No compatibility promise from inherited board definitions |

Check the board label/revision and reported model/ASICs. Gamma Beta15 supports a [single-file application update](single-file-updates.md). QAxe and OctAxe require both files from **one model-specific release asset package**. A common `www.bin` filename does not mean a common web image. Gamma tags use `v0.1.0-beta.N`; QAxe tags use `qaxe-v0.1.0-beta.N`, with on-device version `5tratumFW-qa-0.1.0-beta.N`; OctAxe uses `octaxe-v0.1.0-beta.N` and `5tratumFW-oct-0.1.0-beta.N`. Versions are intentionally family-specific.

Current BETA pairs are Gamma **Beta15**, NerdQAxe++ **Beta12** and NerdOctAxe Gamma **Beta10**, with exact build/source receipts in each family's release manifest and source archive. See [Gamma Beta15](releases/v0.1.0-beta.15.md), [QAxe Beta12](releases/qaxe-v0.1.0-beta.12.md) and [OctAxe Beta10](releases/octaxe-v0.1.0-beta.10.md). All three are built from `747a8fccfa0ef38064753159093f795418ea6b64` and clarify the Save-options-before-waiver flow. Their installed pairs and GET-only actual-browser checks are recorded in [current flow validation](validation-tuning-flow-20261104.md); higher-clock operation remains unqualified. The previous Gamma13/QA10/Oct8 files from `06d2bae5f1a45352a60b9deaf8dc0df34d2d2b89` retain their separate [release validation](validation-autotune-release-20261103.md). Use the [fast-error software validation](validation-autotune-fast-errors-20261104.md), [Tuning guide](autotuning.md) and [5tratumOS update instructions](../DOWNLOADS.md#update-through-5tratumos). Gamma retains ESP-Miner v2.15.4; both Nerd families retain shufps v1.1.1-rc1. Earlier Gamma11, QA8 and Oct6 provenance remains in the [release history](releases/README.md); it does not qualify later images.

The previous physically checked [Gamma Beta10 pair](https://github.com/WillItMod/5tratumFW/releases/tag/v0.1.0-beta.10) remains available. Before returning to it, clear the Ethernet setting and save under Beta11, power off and disconnect the adapter, then install both Beta10 files over Wi-Fi. See [Ethernet instructions](gamma-ethernet.md) and [5tratumOS one-click installation](../DOWNLOADS.md#update-through-5tratumos).

The four owned miners completed supervised updates to Gamma Beta10, QAxe Beta8 and OctAxe Beta5, settings and served-asset verification, pause/resume and a temporary schedule using the existing operating point on 28 October 2026. Both Gammas also passed a subsequent normal software restart. The owner confirmed normal screens and fans on those images, including both fans on each Nerd. Use the [dated validation](validation-aligned-20261028.md) for exact scope; these are not controlled cold power-cycle, changed-point or sustained thermal checks. **Later OctAxe Beta6 check:** production 5tratumOS updater modules invoked by a local QA driver verified the Beta5 → Beta6 application/web pair and retained settings on the owned PCB 2.2 unit; the owner confirmed the standard screen and both fans normal. The installed OS was not upgraded for this test. The original manifest flags remain unchanged. See the [5tratumOS 0.8.48 validation](https://github.com/WillItMod/5tratum/releases/download/v0.8.48/validation-0.8.48.md) and [one-click instructions](../DOWNLOADS.md#update-through-5tratumos). QAxe Beta8 and OctAxe Beta6 expose saved 480×320 RGB/BGR choices, but the actual larger panels remain untested. OctAxe's 480×320 geometry is an accepted working assumption; no controller or vendor flash layout is inferred.

The current OctAxe BETA pair is experimental Beta10. Earlier [Beta6](https://github.com/WillItMod/5tratumFW/releases/tag/octaxe-v0.1.0-beta.6) and [Beta5](https://github.com/WillItMod/5tratumFW/releases/tag/octaxe-v0.1.0-beta.5) retain their own standard-screen evidence. Before a manual downgrade, disable tuning, verify restoration and read the exact journal and screen-profile compatibility requirements. Other boards, flash layouts or larger panels are not qualified by the owned PCB 2.2 observations.

The OctAxe BETA's only admitted build identity remains **BOARD `NERDOCTAXEGAMMA`, reported model `NerdOCTAXE-γ`, BM1370×8**. That identity does not identify a PCB revision or verify regulator population, wiring or flash layout. The [Beta5 installed-device validation](validation-aligned-20261028.md), historical [Beta4 validation](../firmware/nerdqaxe/docs/validation-oct-beta4.md) and earlier Beta1/Beta2 bench records apply only to the owned revision 2.2 assembly with its verified 16 MiB layout; no other OctAxe model or assembly is qualified. [Beta6 software validation](../firmware/nerdqaxe/docs/validation-oct-beta6.md) is separate evidence.

The release contains application, WWW, manifest, SHA256SUMS and corresponding source. Read the manifest board/target and image hashes before upload. Both are OTA partition images, not full factory images. Keep the existing settings and a private unit-specific recovery backup; no automatic presets are applied at boot. Gamma's new authentication settings have a documented [Beta9 journal rollback limit](upstream-migration-20261028.md); an old application/WWW pair alone cannot read an extended journal.

## Repository ownership

- Root `main/`, `components/`, `test/`, `tools/build_5tratumfw.sh` and `version.txt`: Gamma baseline, hardware guard and paired OTA build.
- `firmware/nerdqaxe/`: complete separately maintained Nerd upstream derivative, hardware drivers, display/UI, tests and pinned submodule. QAxe uses `version.txt`, `tools/build_5tratumfw_qa.sh` and `tools/package_5tratumfw_qa.py`; the separate OctAxe family uses `version-oct.txt`, `tools/build_5tratumfw_oct.sh` and `tools/package_5tratumfw_oct.py`. Run these helpers from that directory.
- `docs/installation.md`, `compatibility.md`, `validation-beta*.md`: Gamma-only instructions/evidence.
- [QAxe guide](nerdqaxe.md) and `firmware/nerdqaxe/docs/validation-qa-beta*.md`: QAxe instructions and separate validation.
- [OctAxe guide](nerdoctaxe.md), [build guide](../firmware/nerdqaxe/docs/build-5tratumfw-oct.md), [installation limits](../firmware/nerdqaxe/docs/installation-5tratumfw-oct.md) and [Beta6 software validation](../firmware/nerdqaxe/docs/validation-oct-beta6.md): scoped OctAxe instructions and evidence; earlier installed-device records remain specific to their own images.
- Top-level `.github/workflows/gamma-beta.yml`, `qaxe-beta.yml` and `octaxe-beta.yml`: isolated family validation jobs. They build artifacts and never flash a device or automatically publish stable firmware.

Full QAxe source provenance is pinned in its `SOURCE_ORIGIN.json`. Upstream licenses/authorship remain inside both trees. Adding another model requires an explicit compatibility record, model-specific build/partition contract and separate hardware validation.

The current pairs retain separate family validation records; all earlier release records remain historical evidence for their own images. All families produce OTA partition images only, with no factory or NVS image. QAxe and OctAxe native A/B connections share one ASIC chain and do not establish independent physical-chip work or per-chip coin routing. See [next model qualification](next-models.md).
