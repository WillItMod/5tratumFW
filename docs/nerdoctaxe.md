# NerdOCTAXE-Gamma BETA — scoped compatibility

The current public OctAxe pair is **`5tratumFW-oct-0.1.0-beta.6` — EXPERIMENTAL**, tag [`octaxe-v0.1.0-beta.6`](https://github.com/WillItMod/5tratumFW/releases/tag/octaxe-v0.1.0-beta.6), based on shufps v1.1.1-rc1 and compiled from clean source `5567a2d6c1f59808f197062e565fa6525a93f97b`. The full pinned build and software checks passed. **Later standard-screen check:** production 5tratumOS updater modules invoked by a local QA driver verified the Beta5 → Beta6 application/web pair and retained settings on the owned PCB 2.2 unit; the owner confirmed the standard screen and both fans normal. The installed OS was not upgraded for this test. The larger panel remains physically unqualified, and the original manifest flags remain unchanged. See the [5tratumOS 0.8.48 validation](https://github.com/WillItMod/5tratum/releases/download/v0.8.48/validation-0.8.48.md). See [Beta6 validation](../firmware/nerdqaxe/docs/validation-oct-beta6.md) and [release notes](../firmware/nerdqaxe/docs/releases/octaxe-v0.1.0-beta.6.md).

The [experimental larger-screen support](../firmware/nerdqaxe/docs/octaxe-480-display.md) uses **480×320 = 153,600 pixels** as the accepted working assumption for the reported panel. It adds saved RGB/BGR choices to a **Standard 320×170 default** application/web pair. This assumption does not identify the controller, wiring, PCB or flash layout. No panel is detected automatically: install both Beta6 files, then choose a profile under **Miner controls → Display → Screen**, select **Save this section** and **Restart device**. See [the complete instructions](../firmware/nerdqaxe/docs/installation-5tratumfw-oct.md#select-the-experimental-larger-screen).

The previous physically checked standard-screen [Beta5 pair](https://github.com/WillItMod/5tratumFW/releases/tag/octaxe-v0.1.0-beta.5), compiled from clean source `1a34b24100e1238e331d8145a70f6b08f85f943d`, remains available. It completed supervised OTA, 108 packaged web-record checks, retained-settings checks, pause/resume and a same-point tuning schedule on the owned PCB 2.2 unit. The owner confirmed its screen and both fans normal. That [installed-device evidence](validation-aligned-20261028.md) applies to Beta5 only. Before returning to Beta5, select **Standard 320×170**, save and restart on Beta6, then install both matching Beta5 files.

Its exact target is **NERDOCTAXEGAMMA**, reported model **NerdOCTAXE-γ**, **eight BM1370 ASICs**, and an ESP32-S3 controller. The application asset is `esp-miner-NerdOCTAXE-Gamma.bin`; its `www.bin` belongs to the same OctAxe package. The ASCII asset/mining-agent name and the existing UTF-8 API model name describe the same selected software target.

The owner reported PCB revision 2.2. Its actual 16 MiB flash, 3 MiB WWW and two 4 MiB OTA slots were read and verified before installation, with a private full-flash recovery backup. Regulator strap, stock settings and the pinned revision 2.2 hardware source were reviewed; the regulator package marking was not physically read. Neither the model name nor the compiled eight-chip profile identifies another physical assembly. Other OctAxe models/revisions, NERDOCTAXEPLUS/BM1368, QAxe and Gamma have no compatibility claim from this port. The current [experimental Gamma Beta11](compatibility.md) and [QAxe Beta8](nerdqaxe.md) BETA pairs are separate families; earlier releases retain their own historical records.

The compiled driver retains GPIO3 selection between the inherited four-phase TPS53647 and six-phase TPS53667 paths used by the later 3.0+ designs; it is not hardcoded to PCB 2.2. A revision 3.1 unit matching NERDOCTAXEGAMMA is expected to use this software target, but has not been physically qualified here. Its actual regulator/strap, pinout, cooling/sensors and 16 MiB flash / two 4 MiB OTA slots / 3 MiB WWW geometry must be confirmed separately. See [revision qualification in the installation guide](../firmware/nerdqaxe/docs/installation-5tratumfw-oct.md#regulator-selection-and-later-pcb-revisions). The existing PCB 2.2 evidence remains unchanged.

Pool routing places the Primary/A and Secondary/B editors above ten named slots. Save the connection first, then use **Save to slot** to capture that saved connection with a name. Saved slots offer **Apply to Primary** and **Apply to Secondary**; selecting a slot alone changes no pool. Strict acknowledgment and profile/settings readback checks keep an uncertain write unconfirmed, without automatic replay.

The port retains the unified web navigation, named tuning slots, pool and power schedules, both fans and the branded display, including Beta5's [saved tuning-profile time points](../firmware/nerdqaxe/docs/tuning-profile-schedule.md). Tuning and pool schedules use a fixed UTC offset without automatic daylight-saving changes; the separate pause schedule retains its configured timezone/DST behaviour. **Beta6 exposes experimental saved 480×320 RGB/BGR choices while retaining Standard 320×170 by default.** A QAxe image is never an OctAxe update. The owner confirmed normal overall standard-screen operation on Beta5 and the later Beta6 paired check on the owned unit; eight-chip counter pages and the recurring large logo have not each had a separate physical confirmation. Missing chip temperatures remain unavailable; shared board and regulator readings must not become eight invented chip readings.

Native A/B connections use one stable parent identity, separate sessions and per-session MUX coin/job context. They share the ASIC chain and its existing job selector; `independentWorkAssignment` stays false. From **5tratumOS 0.8.48**, the paired firmware updater discovers compatible published releases independently of separate central Dual pool and Power qualification; **NerdOctAxe Gamma Beta 6** is the newest compatible default. It checks fresh hardware/identity and the package/API contract, without another OS update for each firmware version. See the [one-click instructions](../DOWNLOADS.md#update-through-5tratumos). Separate central Dual pool and Power controls retain their exact-release/model/source qualification; publishing Beta6 or making it installable does not extend those permissions. The miner’s own controls remain available. The central control reviews changes and verifies saved/running mode after any explicit restart. It does not infer support from session advertisements alone or extend physical-board qualification. OS paired updates manage already-qualified 5tratumFW devices; initial conversion from stock firmware uses the identified model's manual application-first/web-second OTA process.

The original Beta6 build record remains software-only; the later paired update adds limited standard-screen evidence for the owned PCB 2.2 unit. It does not qualify the larger panel, a different operating point, a controlled cold power-cycle, sustained thermal stability or every protection fault. Independent physical-chip work routing remains unsupported and disabled.
