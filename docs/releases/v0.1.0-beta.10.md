`5tratumFW-0.1.0-beta.10` · `v0.1.0-beta.10` · compiled/source revision `1645747dfc46a83c52e27c567d43be3f0b53a035`.

**Bitaxe Gamma PCB 601/602 / BM1370×1 / ESP32-S3 / existing 128×32 OLED only.** This public BETA updates the base to Bitaxe ESP-Miner **v2.15.4**, with ESP-IDF 6.0.2, LVGL 9.5.0 and the pinned certificate-bundle update. It retains 5tratumFW's interface, two active routes and ten saved pool slots; it does not enable upstream's eight-active-pool storage or widen hardware support.

**Scheduler → Tuning profile schedule** can select ten saved whole-miner tuning slots at up to sixteen weekly time points. For example, use slot 3 at 00:00, slot 1 at 09:00 and slot 2 at 21:00. Save your intended frequency/voltage pairs first, then configure and enable the schedule. Synchronized network time and an explicit fixed UTC offset are required; tuning and pool schedules do not adjust automatically for daylight saving time. Pauses and hardware protection retain priority. No default schedule, automatic tuning or new operating point is installed.

This release also keeps the configured hostname when discovery names conflict, using a separate runtime alias. Operating-setting writes retain the older compatible journal whenever the new authentication flags match their original stored values.

Download **both `esp-miner.bin` and this release's `www.bin`**. Verify them against `SHA256SUMS` and `manifest.json`; retain `build-provenance.json`, `web-budget.json` and the corresponding `5tratumFW-0.1.0-beta.10-source.zip`. Install the application first through the supported OTA updater, wait for its restart, then install the matching web image and refresh. These are OTA partition images, with no factory, partition-table or NVS image. Do not interchange Gamma, QAxe and OctAxe files. Existing identity, configured clock/voltage, fans, network/pools, ten tuning slots, ten pool slots and schedules are preserved through this update. [Installation guide](https://github.com/WillItMod/5tratumFW/blob/main/docs/installation.md).

**Downgrade caveat:** Beta9 reads the ordinary 28-entry operating journal. Changing either new pool-authentication flag away from its original individual NVS value requires a 30-entry journal that Beta9 cannot read. Restoring both flags to their original values while running corrected Beta10 restores the older format. If those original values are unknown, retain compatible firmware and the unit-specific recovery backup; an old application/web pair alone cannot recover the extended journal. [Migration details](https://github.com/WillItMod/5tratumFW/blob/main/docs/upstream-migration-20261028.md).
