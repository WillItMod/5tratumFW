# Gamma Beta9 — donut candidate screen

`5tratumFW-0.1.0-beta.9` · intended BETA tag `v0.1.0-beta.9`.
**Release preparation; new matched-build and supervised 601/602 checks pending.**

Gamma's block-candidate screen now picks one of six glazed donut designs with
a short caption, difficulty and **BLOCK CANDIDATE / Awaiting pool**. The design
stays stable while that event remains active, avoids repeating the last design,
and settles after six seconds of sprinkle/bob animation. Identification has
its own view; faults, self-test, updates and setup keep their existing priority.

Existing candidate target checks and acknowledgement are retained. A candidate
is not pool acceptance or a verified chain block. No operating point, NVS key,
ASIC driver, pool routing, scheduler, MUX protocol or protection policy changes.

**Gamma PCB 601/602 / BM1370×1 / ESP32-S3 / stock 128×32 OLED only.** Use the
matched `esp-miner.bin` and `www.bin`, manifest, checksums and corresponding GPL
source. Keep each miner's configured clocks, voltage, fans, pools, slots and
schedules. The package contains no factory or NVS image. QAxe and OctAxe use
separate application/WWW pairs; experimental 480×320 QAxe profiles stay separate.

The earlier source-only development checks are recorded separately from this
new version. Exact Beta9 build/source receipt, asset hashes and both supervised
installation results will be added to [Beta9 validation](../validation-beta9.md)
before publication. See [installation](../installation.md) and
[display details](../display-celebrations.md).
